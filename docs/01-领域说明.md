# 领域说明

## 1. 业务背景

本服务面向古籍文物库房的信息化管理，覆盖两条核心业务链：

1. **库房环境异常处置链**：库房/展柜部署温湿度传感器，持续产生环境采样数据；系统依据为各保存等级启用的阈值规则版本对采样进行判定，自动生成异常事件并分级；库房管理员对异常进行隔离保护与保护处置；处置结果须经复核后方可关闭异常，被隔离的藏品方可恢复常态保存。

2. **借展交接链**：外部机构发起借展申请，审批通过后冻结藏品状态、保存等级、包装清单与审批规则快照；出库前须完成覆盖全部藏品与附件的清点，并生成首段交接；运输过程记录运输节点；到馆后进行展陈确认（展柜环境须在借展前置窗口内连续合格）；归还时进行归还清点与归还验收，验收复核结果唯一决定藏品归还后的状态，验收通过后借展关闭。

## 2. 核心概念

| 概念 | 说明 |
| ---- | ---- |
| 藏品（Artifact） | 古籍文物本体，登记后可分配库位、绑定保存等级；不物理删除，只能受约束注销 |
| 附件（Attachment） | 随藏品一并保存/出借的附属物（函套、书签、匣盒等），清点时必须逐一覆盖 |
| 库房/展柜（StorageUnit） | 统一建模为存储单元，`kind=warehouse` 为库房，`kind=showcase` 为展柜 |
| 保存等级（PreservationLevel） | 藏品的保存要求分级（如特藏、一级、二级），决定其环境阈值 |
| 阈值规则版本（ThresholdRuleVersion） | 针对保存等级的温湿度阈值，带版本号，草稿→启用→退役，任一时刻一个等级仅一条启用版本 |
| 传感器（Sensor） | 绑定在存储单元上的温湿度传感器，产生环境采样 |
| 环境采样（EnvSample） | 传感器上报的一次温湿度读数，含采样时间与接收时间，迟到数据仅存档不参与状态变更 |
| 异常事件（AnomalyEvent） | 环境越界触发的异常，按连续越界次数分级（轻微/严重/危急），有关闭前不得出库的约束 |
| 保护处置（ProtectionAction） | 对异常的处置动作（隔离、转移、除湿等），处置后须复核 |
| 借展申请（LoanApplication） | 借展全流程载体，审批时冻结藏品状态、保存等级、包装清单与审批规则快照 |
| 出入库清点（InventoryCheck） | 出库/归还两个方向的清点，必须覆盖借展全部藏品与附件，使用幂等键防重 |
| 包装交接（PackageHandover） | 包装随责任的转移记录，时间严格递增，交接人身份不得连续重复替代 |
| 运输节点（TransportNode） | 运输途中出发/中转/到达节点，时间与序号递增 |
| 展陈确认（ExhibitionConfirm） | 借展方确认上展，前置校验展柜环境连续合格 |
| 归还验收（ReturnAcceptance） | 归还清点后的复核验收，其结果唯一决定藏品归还后的状态 |
| 历史快照（Snapshot） | 每次环境数据（采样表只增不改）与每次藏品状态变更（快照表）均永久保留 |
| 审计（AuditLog） | 关键写操作均记录审计日志，随业务事务一同提交或回滚 |

## 3. 关键业务约束

1. **借展冻结**：审批通过瞬间，将每件借展藏品的当前状态、保存等级、包装清单（全部附件）以及审批所依据的启用阈值规则，整体快照冻结到借展单上；后续冻结依据以快照为准。
2. **前置环境窗口**：借展审批（库房环境）与展陈确认（展柜环境）时，要求对应存储单元在配置的前置窗口（默认 72 小时）内采样连续合格：窗口内无任何越界采样，且采样覆盖度满足最大间隔约束（默认 60 分钟）。
3. **异常未关闭不得出库**：借展藏品所在存储单元存在未关闭异常事件时，出库清点一律拒绝。
4. **清点全覆盖**：出入库清点必须覆盖借展单内全部藏品与全部附件，缺一即拒绝；清点结果与冻结包装清单的差异可查询。
5. **交接有序**：同一借展单内包装交接的交接时间必须严格递增；交接人身份不得与上一段交接人重复（防止同一身份连续替代）；交接链必须连续（本段交出方=上段接收方）。
6. **归还状态唯一来源**：归还后的藏品状态只能由归还验收的复核结果更新（通过→恢复常态；带意见通过→恢复常态并记录意见；不通过→转入隔离），任何直接修改均被拒绝。
7. **迟到数据不覆盖验收**：采样时间早于某借展单验收完成时间的环境数据，标记为迟到数据，仅入库存档，不触发异常判定，不改变已完成的借展验收结论。
8. **幂等与并发**：重复的清点与交接请求使用幂等键去重，重复提交返回首次结果；可变实体携带版本号，更新采用乐观锁，冲突返回 409。
9. **受约束注销**：藏品不提供物理删除；仅常态（已登记/在库）藏品可注销，注销须给出理由并保留全部历史与审计。
10. **事务完整性**：异常隔离与处置、出库清点与首段交接、归还验收与借展关闭，均在同一个真实 SQLite 事务内完成，任一步失败整体回滚。

## 4. 后台作业

系统内置可重启恢复的后台作业调度器，作业持久化在 `jobs` 表：

- **环境巡检（patrol）**：周期扫描未处理的环境采样，依据启用阈值规则生成/升级异常事件。
- **借展到期（loan_due）**：周期扫描超过应还日期仍未关闭的借展单，标记逾期并记录审计。
- **交接超时（handover_timeout）**：周期扫描在途超过超时阈值仍未推进的借展单，记录超时告警。
- **失败重试**：作业执行失败按指数退避重试，超过最大尝试次数标记为失败终态；进程重启时将中断的 `running` 作业恢复为 `pending` 继续执行。

## 5. 技术要点

- 单进程 Go HTTP JSON 服务，`database/sql` + 嵌入式 SQLite（modernc.org/sqlite，纯 Go，无 CGO），持久化到 `DB_PATH` 文件，不使用 `:memory:`。
- 分层：配置 / HTTP / 服务 / 领域模型 / 规则 / Repository / SQLite / 事务 / 审计 / 后台作业。
- 时钟可注入（`clock.Clock`），测试使用假时钟精确控制时间窗。
- 分页采用基于主键的键集分页（cursor + limit），保证稳定排序。
